## 填写规则（收口前必读）

### 状态取值

| 状态 | 含义 | 证据要求 |
|---|---|---|
| 通过 | 该用户路径已实测，结果符合预期 | 证据列必须是非空真实路径或 `ext:` / `self:` 引用；证据类型、置信度、时间、commit 必填 |
| 未交付-失败 | 实测结果不符合预期，或实现不达标 | 证据列必须能复现失败；判据写清实际读数与预期差 |
| 未交付-阻塞 | 外部条件缺失，无法完成实测 | 必须同目录有填满的 `blocking-form.md`，07 证据列写 `self:#阻塞举证` |
| 未覆盖 | 尚未取证 | 证据类型、证据、置信度、时间、commit 可填 `—`；收口时仍未取证，包结论按 `未交付（失败）` 记，不能写通过或阻塞 |

### 包结论

按从上到下第一条命中的规则取值：

| 账本状态组合 | 包结论 |
|---|---|
| 任一 `未交付-失败` | `未交付（失败）` |
| 否则任一 `未交付-阻塞` | `未交付（阻塞）` |
| 否则任一 `未覆盖` | `未交付（失败）` |
| 全部为 `通过`，但旅程卡缺失或未通过 | `未交付（失败）` |
| 全部为 `通过`，且至少一张旅程卡通过、无未解决不变量 | `通过` |

包结论只允许 `通过` / `未交付（失败）` / `未交付（阻塞）` 三种，不写其他措辞。

### 十列写法

| 列 | 写法 |
|---|---|
| 验收项 ID | 稳定编号，字母开头，如 `TC-00-01`、`EDIT-01`；同批不重复 |
| 用户路径 | 写 `J-xx / 步骤 n`，对应旅程卡；没有旅程 ID 的行只能算单点检查，不支撑批次通过 |
| 预期 | 用户看到什么算对；写可判定的现象或读数 |
| 证据类型 | 六选一：`截图` / `布局树` / `像素` / `DB` / `日志` / `性能` |
| 证据 | 仓库相对路径、`ext:EXT-01` 或 `self:#阻塞举证`；文件必须真实存在 |
| 产出者 | 人、角色或脚本名，能追到具体产出者 |
| 置信度 | `高` / `中` / `低` |
| 时间 | 证据产出日期，`YYYY-MM-DD` |
| commit | 7-40 位十六进制，或 `工作区`；必须等于版本锚点或为其祖先 |
| 状态 | 四选一：`通过` / `未交付-失败` / `未交付-阻塞` / `未覆盖` |

### 证据边界

- 证据文件存在不等于证据有效；截图内容、布局树属性、像素差、性能读数是否达标，由对应判据门禁判断。
- 禁止用旧版本截图、旧日志、他人批次的证据充当本批证据。
- `未交付-阻塞` 的证据列写 `self:#阻塞举证`，并在本文件「阻塞举证」段引用同目录 `blocking-form.md`。
- 外部件必须先在「外部证据登记」登记 `EXT-01`，再在证据列写 `ext:EXT-01`。
