# 修缺陷模式

> 先证明缺陷存在，再证明根因成立，最后证明修复有效。六步，缺一不可。

## 0. 适用边界

用于已有行为与预期不符：报错、结果不对、状态不一致、偶发失败、性能退化。

不用于：

- 系统原本没有这个能力——走 `references/new-feature.md`。
- 只做验收、不改代码——走 `references/acceptance.md`。
- 一批改动准备对外——走 `references/release.md`。

**核心禁令：不读代码猜着改。** 读代码只能产生假设，不能证明根因；根因必须由复现、日志或最小实验支撑。

## 1. 六步流程

| 步骤 | 要做什么 | 产出 | 出口条件 |
|---|---|---|---|
| 1 复现 | 按原始入口稳定重现，留下失败证据 | `01-缺陷记录.md`、`02-复现记录.md` | 预期与实际可对照，失败可重复 |
| 2 日志定位 | 沿完整链路打日志，找首次分叉 | `03-根因分析.md` 的日志证据 | 能指出实际与预期从哪一步开始不同 |
| 3 根因四问 | 回答四个问题，形成可证伪的根因陈述 | `03-根因分析.md` | 四问都有证据，不用“代码写错了”搪塞 |
| 4 最小修复 | 只改根因，补回归测试 | 代码、测试、`04-修复与回归记录.md` | 修复前测试红，修复后测试绿 |
| 5 回归 | 原缺陷、相邻路径、错误路径和数据兼容都复验 | `04-修复与回归记录.md` | 原复现项通过，回归项有证据 |
| 6 独立复核 | 非执行者重跑复现和关键回归，审 diff | `04-修复与回归记录.md` 的复核结论 | 复核通过；作者不能给自己判通过 |

## 2. 每一步的硬要求

### 2.1 复现

按用户实际使用的入口走，不用内部接口或另一条启动路径替代。记录：

- 前置条件：数据、账号状态、配置、版本。
- 最小步骤：从哪个入口开始，每一步做什么。
- 预期结果与实际结果。
- 复现频率：每次、偶发、只在特定数据下。
- 失败证据：报错、日志、截图、错误读数，必须能定位到文件和行。

**复现不了怎么办**：先查环境、数据、入口差异，补充日志或换条件再试；把已经排除的可能写进 `02`。仍然复现不了，不进入修复，按“未复现”记录。若缺的是外部环境或权限，按 `templates/blocking-form.md` 填举证单。不要因为“看起来像某个问题”就改代码。

产出：`01-缺陷记录.md` 和 `02-复现记录.md`。

### 2.2 日志定位

沿完整链路铺日志，而不是只在出错那行打一条：

```text
用户操作或系统事件 → 状态层 → 命令或接口 → 数据层 → 持久化 → 界面或输出回刷
```

要求：

- 一次把关键节点打全，避免“改一点、跑一次、加一条日志”来回折腾。
- 每条日志带：输入、关键状态的前后值、走了哪个分支、错误码或异常。
- 用同一组操作对照“预期路径”和“实际路径”，找第一次出现差异的位置。
- 日志是临时取证工具；修复完成后删净并重新构建或运行，确认产品不再输出调试日志。

产出：`03-根因分析.md` 的“日志与首次分叉”一节。

### 2.3 根因四问

四个问题必须逐个回答，每个答案都要有证据：

| # | 问题 | 不合格回答 | 合格回答 |
|---|---|---|---|
| 1 | 实际行为是什么？ | “感觉不对”“有时候会挂” | “输入 X 时输出 Y，日志第 N 行显示状态 Z” |
| 2 | 预期行为是什么？ | “应该是正常的” | “任务卡 AC-2 规定应输出 W；用户也确认过” |
| 3 | 两者首次分叉在哪？ | “某个模块里” | “在 A 调用 B 时，B 收到的参数少了一个字段，导致分支走错” |
| 4 | 为什么现有逻辑会产生这个分叉？ | “代码写错了” | “B 假定字段一定存在，但上游在空值时省略字段，B 没有默认值分支” |

把四问收敛成一句可证伪的根因陈述：

```text
当 <触发条件> 时，<位置或组件> 把 <输入或状态> 当成 <错误假设>，
于是 <实际行为>；预期应是 <预期行为>。
把 <约束、顺序或边界> 改为 <修正> 后，<可观察的预测>。
```

如果写不出这句，或者第 3、4 问答不上来，说明根因还没找到。回去补日志或做最小实验，不要开始改代码。

**同因普查**：根因确认后，搜索同一模式是否还在别处出现。列出命中点；在当前缺陷范围内的一起修，范围外的另立缺陷，不假装没看见。

产出：`03-根因分析.md`。

### 2.4 最小修复

- 修根因，不修症状。报错消失不等于缺陷修好。
- 只改与根因直接相关的代码；不顺手重构、改名、升级依赖、格式化无关文件。
- 先写一个能复现缺陷的测试，确认它在修复前失败；再改代码让它通过。
- 回归测试是本次新增时，测试和修复同一次提交；回归测试是基线已有且已能复现时，修复提交可以只改生产代码，测试文件不动。同类普查或重构另开提交。
- 修复会跨模块、改数据结构或触及破坏性操作时，停下来补方案和审批，不硬改。

产出：代码、测试，以及 `04-修复与回归记录.md` 的“改动与最小性”一节。

### 2.5 回归

至少覆盖四类：

1. **原缺陷**：按 `02` 的最小步骤重跑，预期结果通过。
2. **相邻路径**：同一入口的其他分支、同一模块的相近功能。
3. **错误与边界**：空值、非法输入、超限、并发或超时。
4. **数据与兼容**：旧数据、迁移前后、导入导出或持久化格式。

每条回归都要有 A 级读数，或两条不同通道的 B 级观察。记录修复前后的对照；同一张截图的不同裁剪、同一条日志的两行，不算两类证据。

**负对照**：至少用一个坏样本证明检查会报红。测试永远绿，可能只是没断言到。

产出：`04-修复与回归记录.md` 的“回归矩阵”一节。

### 2.6 独立复核

复核者不能是修复作者。可以是另一个人，也可以是另一个不共享作者结论的会话或代理。

复核者拿到：`01`–`04`、完整 diff、复现步骤和测试命令。复核动作：

- 按 `02` 重跑最小复现，确认修复前失败、修复后通过。
- 抽查关键回归，不只看作者贴的截图。
- 检查修复是否对应第 4 问的机制，而不是把报错藏起来。
- 检查 diff 有没有计划外改动、调试代码或数据破坏风险。

复核结论只有两种：通过，或列出问题并退回。作者不能给自己写“通过”；没有独立复核时，`04` 记“待复核”，交付不能写通过。

## 3. 01–04 四份记录

| 文件 | 必写 | 不写 |
|---|---|---|
| `01-缺陷记录.md` | 缺陷 ID、标题、来源、影响、环境、预期与实际、发现时间、状态 | 猜测的根因、修复方案 |
| `02-复现记录.md` | 前置条件、最小步骤、频率、失败证据、影响范围、已排除项 | 实现细节、未经证实的推断 |
| `03-根因分析.md` | 日志锚点、首次分叉、根因四问、根因陈述、同因普查、方案对比 | 大段代码、修复后的自我评价 |
| `04-修复与回归记录.md` | 提交、改动清单、最小性理由、测试前后对照、回归矩阵、独立复核结论、残余风险 | 与本次缺陷无关的顺手改动 |

如果这次修复属于一个批次，`07-验收回归清单.md` 仍是唯一状态源；`04` 只放修复证据，不另立一套“已修复”状态。

## 4. 不读代码猜着改

| 可以做 | 不可以做 |
|---|---|
| 读代码形成假设，标出待验证点 | 看到某行“像错的”就直接改 |
| 沿调用链找候选分叉点 | 把“代码写错了”当根因 |
| 用日志或最小实验验证假设 | 加 try/catch、延迟、重试让现象消失 |
| 对照任务卡或规格确认预期 | 用清库、重置数据掩盖缺陷 |
| 一次只验证一个假设 | 同时改三处，事后说不清哪处生效 |

动手前必须能回答：**哪条日志、哪个实验或哪条复现证据证明了这个根因？** 答不上来就还没到改代码的时候。

## 5. 回归范围

| 范围 | 至少要验什么 |
|---|---|
| 原入口 | 用户最初触发缺陷的完整路径 |
| 同模块相邻功能 | 共用状态、命令、数据或生命周期的路径 |
| 错误路径 | 空值、非法输入、权限不足、超时、重复操作 |
| 数据兼容 | 旧数据读取、迁移、回滚或恢复 |
| 平台与版本 | 声明支持的环境各一条证据；没测的从声明里删掉 |

性能缺陷另加：同环境、同夹具、至少三次采样，写清分布和阈值；单次最快值不算结论。

## 6. 停止条件

出现以下任一情况，停下来记录，不硬推：

- 按原始入口和最小步骤始终复现不了，且环境、数据、入口差异都查过。
- 第 3、4 问答不上来，只能靠猜。
- 修复需要跨模块重构、改数据结构或做不可逆操作，超出当前任务卡。
- 没有独立复核者，或复核者就是作者。
- 修复会让已有能力退化，且没有兼容或回滚方案。

停下来不是失败：把已确认的事实、排除项和下一步写进 `03` 或举证单，比改错代码更有价值。

## 7. 收口自检

- [ ] `01`–`04` 齐全，每份只写自己该写的。
- [ ] 复现步骤能从原始入口重跑，失败证据可定位。
- [ ] 根因四问都有证据，根因陈述能被修复结果验证。
- [ ] 修复前测试红、修复后测试绿，代码和测试同提交。
- [ ] diff 没有计划外改动、调试日志或数据风险。
- [ ] 原缺陷和回归矩阵都有达标证据，负对照会报红。
- [ ] 独立复核通过，复核人不是作者。
- [ ] 同因普查的漏网项已记录，不静默放过。
