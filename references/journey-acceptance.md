# 用户旅程验收

> 本文件补的是“连续使用”这一层，不是再列一遍功能点。它只回答一件事：用户从入口走到目标时，屏幕各区域是否始终在说同一件事。
>
> 下文用“列表 / 条目 / 详情”指代任意可选中对象；换成你项目的领域词即可，示例不是领域绑定。

## 0. 为什么需要

功能点全绿，不等于用户路径成立。

典型漏法：

- 切右侧页签，右侧内容变了，左侧列表还选着上一页。
- 新建条目后列表不刷新，用户以为没建成。
- 搜索无结果时中栏空白，清空关键词后计数和列表又对不上。
- 移动条目后详情页还显示旧分组。

这些问题的共同点不是某个按钮坏了，而是：单点证据都成立，**跨区域不变量不成立**。只按功能点打勾，就会漏掉它们。

本文件不定义第二套状态。旅程结论只写在旅程卡里，07 账本仍是一条验收项一行，并在“用户路径”列引用旅程 ID。

## 1. 一条旅程卡

每批至少 1 条，跨区域或多步骤改动至少 3 条。一条旅程控制在 3–7 步；超过 7 步就拆成两条，不要做成一张很长的清单。

一条旅程必须写清：

- **用户目标**：用户想完成什么，用用户的话写，不写函数名。
- **入口与前置**：从哪个入口进，当前数据、窗口、登录/锁定状态是什么。
- **步骤**：每步只写一个用户动作，动作后写“用户看到什么变化”。
- **跨区域不变量**：这一步之后，哪些区域必须互相对得上。
- **结束状态**：完成后停在哪、数据是否保存、能不能退出/撤销。
- **异常分支**：本批涉及的空白、无结果、失败、权限不足至少走一条。
- **证据**：整窗截图、布局/读数、DB/日志、步骤时间线。

模板见 `templates/journey-card.md`。

## 2. 跨区域不变量

这是本文件的核心。每条旅程至少选 3 条不变量；有左侧列表、中间内容、右侧详情或页签的界面，至少选“身份”和“选中/焦点”两条。

| 不变量 | 要断言什么 | 常见失败样子 |
|---|---|---|
| 身份一致 | 左列表选中的对象 = 中栏当前对象 = 右栏标题/详情 = DB 当前 ID | 右侧换页，左侧还选旧页 |
| 计数一致 | 表头计数 = 可见卡片数 = 当前筛选下的 DB 查询数 | 显示“14 个”，中栏却写“还没有条目” |
| 选中/焦点一致 | 同一时刻只有一个选中项；选中态可见；焦点所在区域与当前操作一致 | 选中背景消失、焦点停在已关闭的弹层 |
| 保存一致 | 编辑后状态、自动保存提示、重新打开后的内容一致 | 显示已保存，重开还是旧内容 |
| 空/错误一致 | 空态/错误态有原因、有下一步、有退出路径；计数不为假 | 空白页没有文案，也没有退出搜索 |
| 禁用/权限一致 | 按钮可用状态与当前数据/权限一致 | 空列表仍显示可点的删除 |
| 导航一致 | 面包屑、页签、标题、返回位置与当前内容一致 | 页签显示 B，内容还是 A |

读取规则：

- 选中背景、边框、焦点环优先用**整窗截图 + 像素采样**；布局树工具经常读不到背景色和边框。
- 计数、身份、保存状态至少再读一路 DB、日志或接口，不能两路都来自界面自述。
- 只看到“这一屏没有”不能推出“整个流程没有”；先确定它应该出现在哪个区域，再去那里找。

## 3. 证据怎么留

一条旅程至少留三类证据：

1. **整窗前后截图**：关键步骤各一对，必须包含左、中、右/页签的完整窗口，不能只裁当前检查项。重点步骤是进入、切换、提交、清空、退出。
2. **状态读数**：布局树/无障碍树、DB、接口返回、日志中的至少一种；身份和计数优先用 DB 或接口读数。
3. **步骤时间线**：每一步的时间、动作、可见结果；出现不一致时，能回到具体哪一步。

如果只截了局部图，结论最多覆盖那张图拍到的区域，不能写“整页正常”。截图和读数冲突时，先重做取证，不要挑对自己有利的一路。

## 4. 不按清单的 5 分钟

每批留一段 5 分钟左右的真实使用：不按检查表，从用户入口连续走到目标，再回到列表/首页。目的不是替代回归，而是打破“只验自己列过的项”。

- 发现跨区域不一致、空白、焦点丢失、计数矛盾，先记观察，不急着判产品失败。
- 能重复两次的，转成 TC 或新的不变量；不能重复的，写清环境和尝试次数，留作观察。
- 这一段不写“通过”，只写“有无新发现”。

## 5. 批次通过条件

一批要判通过，必须同时满足：

- 至少一张旅程卡结论为“通过”，覆盖本批主要用户目标；
- 07 账本全部验收项为通过或不适用；
- 没有未解决的跨区域不变量；
- 不按清单的使用没有留下未分级的新发现；
- 旅程卡、07、证据三者能互相对上。

**只打勾、只截局部、只验右侧内容变了，不能判批次通过。** 如果旅程卡没做，批次最多记“未覆盖”；如果旅程失败，即使 07 全绿，整批也不能通过。

纯 API、CLI、数据迁移等没有界面的任务可以写“不适用”，但要写明理由和替代路径，不能因为“没有界面”就跳过用户目标。

## 6. 反模式

- “右侧内容变了”就判切换成功，不看左侧选中项。
- “按钮能点”就判操作成功，不看点击后的列表、计数、DB。
- “截图看起来正常”就判整页正常，实际只截了一个角。
- “布局树工具没有选中属性”就认为没有选中态；这通常只是读不到。
- “所有检查项都过了”就收口，没有一条连续用户路径。
- 把旅程卡写成第二条 07：每步一个状态、每步一个复核人。旅程卡只写路径和不变量，状态仍回到 07。

## 7. 一个短例子

三栏列表应用（示例），目标“从列表打开 A，切到 B 页签，再搜索一个不存在的词”：

| 步骤 | 用户动作 | 可见结果 | 跨区域不变量 |
|---|---|---|---|
| 1 | 左侧点条目 A | 中栏显示 A 的内容，右栏标题为 A | 左选中 A = 中栏 A = 右标题 A = DB 当前 A |
| 2 | 右栏点页签 B | 右栏显示 B 的内容 | 左选中 B = 中栏标题 B = 右页签 B |
| 3 | 顶部搜索“不存在词” | 中栏出现空态、退出搜索 | 空态文案可见；退出按钮可点；计数不显示旧值 |
| 4 | 清空搜索 | 回到条目列表 | 表头计数 = 可见卡片数 = DB 查询数 |

第 2 步就是“单点全绿、跨区域失败”的典型：只看右栏会通过，必须同时看左栏选中项。

## 8. 收口自检

- [ ] 每批至少一张旅程卡，步骤 3–7 步，入口是用户入口。
- [ ] 每条旅程至少 3 条跨区域不变量，身份和选中/焦点已覆盖（有对应界面时）。
- [ ] 有关键步骤的整窗前后截图，不是局部裁图。
- [ ] 身份/计数/保存至少有一路 DB、日志或接口读数。
- [ ] 做了 5 分钟不按清单的使用，新发现已分级。
- [ ] 批次结论同时引用旅程卡和 07，不只写“检查项全过”。
