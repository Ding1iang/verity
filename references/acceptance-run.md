# 验收执行参考

> 本文件可独立使用，不要求先读 `SKILL.md`。它只回答“一条验收项怎么从待验走到有证据”，不定义第二套状态；状态和落账以 `references/acceptance.md` 为准。

## 0. 适用边界

- 用于验收模式，也用于新功能和修缺陷的收口。
- 不用于设计、实现或发布决策；不替项目决定“该不该做”。
- 视觉的“看见什么”见 `references/visual.md`，行为/性能的“变了多少、快了多少”见 `references/behavior-perf.md`，证据分级见 `references/evidence.md`。

## 1. 开测前

### 1.1 记锚点

每条证据必须能回答：在哪个版本、哪个环境、什么输入、什么时间、由谁取得。开测前先把这五项写进批次信息；中途换版本，按 `references/evidence.md` 的锚点规则重判，不能把旧证据挂到新版本上。

### 1.2 找预期

预期只从任务卡的验收项来。没有任务卡，先立卡；任务卡没写判据，先补判据。规格缺失或过时，可以按用户可见常识补一条，但必须在账本里注明“预期来源：常识/规格缺口”，并同时记一条待补规格；不要把补出来的预期冒充正式判据。

### 1.3 备数据

- 用满足判据的最小数据；不删、不重置既有数据来制造“干净起点”。
- 记录测试留下了什么：新建文件、账号、缓存、临时目录；收口时按任务卡清理。
- 真实数据和测试数据分开；敏感值脱敏后再进证据。

### 1.4 选通道

- 走用户入口和完整用户路径，不拿内部接口、调试菜单或数据库直读代替用户操作。
- 记录工具与版本：浏览器、设备、系统、屏幕尺寸、网络条件；视觉按 `visual.md` 的视口矩阵，行为/性能按 `behavior-perf.md` 的采样规则。
- 先确认目标可见、可点击、可聚焦；操作没命中目标，记“操作无效，需重测”，不记产品失败。

## 2. 单条执行

| 步骤 | 做什么 | 留下什么 |
|---|---|---|
| 1 定位 | 从原始入口走到被测项，记完整路径和前置状态 | 路径、截图或录屏、起始状态 |
| 2 操作 | 按真实用户动作执行；一次只改一个条件 | 输入、操作序列、时间 |
| 3 观察 | 同时看画面和读数：截图/几何 + 文字/节点/日志/命令输出 | 截图、读数、文件或命令定位 |
| 4 判级 | 对照最低证据等级；证据覆盖小于结论就降级或缩小结论 | 证据等级、理由 |
| 5 落账 | 一项一行写进 07；写状态、证据定位、复核人 | 账本行 |

观察至少两路，且不能两路都来自被测应用自己。一路是画面（截图、像素、布局），另一路是文字或读数（无障碍树、DOM、接口返回、文件、日志、命令输出）。两路冲突时，先按 `references/evidence.md` 的 F1/F2 查“把被测界面当事实源”和“把没看到当不存在”，不要挑对自己有利的一路。

## 3. 判定与状态

> 状态定义以 `references/acceptance.md` 第 2 节为准；下面只是执行时速查，不另立状态。

- 通过：达到该项最低证据等级，且证据覆盖判据的全部范围。
- 未通过：实际结果与判据不符，或证据不足、覆盖不全。未通过可以带原因，但不能带“基本可用”。
- 阻塞：按 `templates/blocking-form.md` 填齐环境、注入通道、判据、数据四维和正对照，仍然无法取证；填不出举证单就写未通过。
- 不适用：任务卡明确把该项排除在本次范围外，并写了理由；不适用不是“没验”。
- 待验/验中/待定：过程状态，收口前必须落成通过、未通过、阻塞或不适用之一。

如果项目有自己的旧状态词，只在项目适配层做转换，不要把旧词带进 07；07 只写 `references/acceptance.md` 第 2 节的七态。项目若需要展示欠账，只能在项目层把未通过项列成欠账表，不能改 07 的状态列。

## 4. 批量验收

- 先挑一个最小、最独立的项试通全流程，确认版本、数据、工具和账本都能用，再按功能域分批。
- 同一批只用一个版本锚点；中途换版本，重新开一批，旧结论保留但不复用。
- 从 07 断点续接，不靠记忆；每批结束更新“已验/未验/卡在哪一句话”，不攒到最后。
- 跨功能依赖单独列一行，写清依赖谁、卡在哪；依赖未通过时，下游项最多记待验，不能记通过。

## 5. 失败归因

先把失败分到三类，再决定下一步：

| 类型 | 判据 | 处理 |
|---|---|---|
| 产品不符合预期 | 同一路径可重复，换通道仍出现 | 记未通过，保留证据 |
| 操作方法不对 | 目标没点中、前置状态没造对、步骤顺序错 | 记“操作无效，需重测”，修方法后重来 |
| 环境/通道受限 | 工具、设备、权限、数据不可用 | 先换通道；仍不行按阻塞举证单 |

- 判“没有 X”之前，先说清“X 出现时应该在哪”，再去那里找；只写“这一屏没有”不能推出“整篇没有”。
- 实测结果与已核实的前提冲突时，两边都复核：重做取证，同时查前提的出处和时效；不要只怀疑测法，也不要只怀疑前提。
- 视觉实现与代码/规格冲突时，默认记未通过；只有明确标注“待确认”并进入异常队列时才允许暂挂，不能判通过。
- 环境受限不是免检牌：必须写卡点、试过的路、替代证据；四维没试全，只能记待验，不能写阻塞。

## 6. 复测与证据复用

- 复测已修项必须补新版本戳，旧结论不删；只重测受影响域，不把未受影响项重新判一遍。
- 测试方法本身错了，也要留痕：记“方法错误，结论作废”，不要静默删掉旧行。
- 证据复用必须同时满足 `references/evidence.md` 的五个条件（同一版本、同一环境、同一输入、同一任务卡版本、同一判据）；缺一项就重新取证。
- 截图不能只截“成功那一角”；至少包含被测项、前置状态和能定位版本的界面或读数。

## 7. 收口自检

- [ ] 每条验收项在 07 里恰好一行，状态是七态之一。
- [ ] 每个“通过”都有达到最低等级的证据，证据路径/命令真实存在。
- [ ] 没有“基本可用”“通过（含残余）”“带欠账”等旧词。
- [ ] 未通过项写清实际与预期的差异；阻塞项有举证单；不适用项有范围理由。
- [ ] 批次信息有版本、环境、日期、执行者；复测项有新版本戳。
- [ ] 临时数据、脚本、截图已按任务卡清理或登记保留。
