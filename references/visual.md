# 视觉验收参考

> 本文件可独立使用，不要求先读 `SKILL.md`。它只回答一件事：界面视觉改动怎样算做到，以及怎样证明。
>
> 视觉结论最终仍写进 `07-验收回归清单.md`；本文件不定义第二套状态。
>
> 纯视觉优化（“觉得丑”类）的设计侧和落地侧见 `references/ui-improvement.md`；本文件负责验收。

## 0. 适用边界

用于界面视觉、布局、响应式、主题、可读性、焦点和动效的验收。纯逻辑、接口、数据迁移不走本文件；那些走行为与性能参考。

“看起来不错”不是判据。视觉任务必须先把“看什么、在哪个窗口、哪个状态、什么算不合格”写成可判的句子，再开始截图或操作。

## 1. 视觉任务卡

视觉任务卡是普通任务卡的视觉版本。下面这些字段在动工前必须填；缺一项就不开工。

| 字段 | 必填 | 写什么 | 不合格示例 |
|---|---|---|---|
| 任务编号与版本 | 是 | 稳定 ID 和 `v1`、`v2`；判据一改就升版 | “这次改界面” |
| 视觉目标 | 是 | 一句话，能判真假 | “优化视觉效果” |
| 参照物 | 是 | 设计稿、设计令牌版本、基线截图；没有参照物时只判可测规则，不判“像不像” | “参考一下那个页面” |
| 视口矩阵 | 是 | 宽度 × 高度、横竖屏、缩放比例；至少窄、中、宽三档 | “常见屏幕” |
| 主题与字体 | 是 | 浅色 / 深色 / 高对比；100% / 200% 字体 | “默认主题” |
| 七态矩阵 | 是 | 视觉七态 × 视口 × 主题，必测格打勾；不能测的格写原因 | “状态都看一下” |
| 验收项 | 是 | 每条含 ID、判据、最低证据、取证路线 | “按钮正常” |
| 约束与红线 | 是 | 不能破坏的既有能力、不能碰的数据或页面 | 空着 |
| 三路取证 | 是 | 结构/几何、像素/视觉、交互/路径各准备什么 | “截几张图” |
| 模型候选 | 是 | 模型提出的疑点清单；标明“待验证”，不得写成结论 | 把模型评语当通过 |
| 版本锚点与环境 | 是 | commit 或构建号、系统、浏览器/运行时、字体、缩放 | “最新版” |
| 执行者与复核者 | 是 | 两个角色；高风险视觉改动必须独立复核 | 全写自检 |

### 1.1 七态

七态是本技能包的默认视觉矩阵：

| # | 状态 | 怎么进入 | 看什么 | 不合格示例 |
|---|---|---|---|---|
| 1 | 默认 | 不悬停、不选中、无输入 | 初始层级、间距、对齐、文字完整 | 首屏就截断标题 |
| 2 | 悬停 | 指针停在可交互元素上 | 反馈是否出现、是否只靠悬停才给关键信息 | 悬停才显示唯一入口 |
| 3 | 选中 | 当前项、开关、标签页被选中 | 选中态是否持久、是否和悬停态可区分 | 选中和悬停长得一样 |
| 4 | 禁用 | 条件不满足或权限不足 | 仍能读清文字，不误导为可点击 | 只降透明度到看不清 |
| 5 | 加载 | 请求未完成、内容未就绪 | 有进度反馈，布局不跳，能取消或重试 | 白屏转圈，内容到位后整页跳 |
| 6 | 空 | 没有数据或首次进入 | 说明为什么空、下一步做什么 | 只有一片空白或一个“0” |
| 7 | 错误 | 请求失败、校验失败、权限失败 | 说清发生了什么、保留输入、给重试 | 只弹“出错了” |

“聚焦”和“按下”是横切检查，不另立第八态：每个可交互元素都必须有可见焦点和按下反馈。项目可以把它们加成独立状态，但不能从七态里减掉任何一个。

### 1.2 视口矩阵怎么定

至少覆盖三档，并写清每档的实际尺寸，而不是只写“手机 / 平板 / 桌面”：

- 窄档：项目声明支持的最小宽度。没有声明时，用 320 CSS px 作为回流检查下限。[S7]
- 中档：常见分栏切换点，例如 768 或 800 宽。
- 宽档：项目声明的最大内容宽度或桌面常用宽度。
- 每个视口都要写明高度、横竖屏、浏览器缩放和字体缩放；只改宽度不改字体，不能证明 200% 字体下的表现。[S6]
- 窗口从宽到窄、从窄到宽各走一遍；只测一个方向会漏掉折叠/展开不对称的问题。

## 2. 三路取证

三路是三种不同通道，不是三张截图。

| 路线 | 取什么 | 能证明什么 | 等级与注意 |
|---|---|---|---|
| 结构 / 几何 | DOM 或无障碍树、元素边界、`scrollWidth` / `clientWidth`、层级、Tab 顺序 | 有没有溢出、重叠、遮挡、顺序错误 | 机器可复算的读数记 A；只读代码推断记 C |
| 像素 / 视觉 | 每个状态 × 视口 × 主题的截图；颜色采样、对比度、像素差、文字边界 | 实际画出来是什么样，颜色和间距是否达标 | 可复算的像素读数记 A；单张局部截图只是 B，不能支撑整页 |
| 交互 / 路径 | 按真实入口悬停、聚焦、点击、键盘操作；记录前后状态和日志 | 状态真能进入、能退出、键盘可用、失败可恢复 | 真实操作路径的现场观察记 B；界面读数加存储/网络读数可互证为 B+B |

三条硬规则：

1. **路线不能互相冒充**：同一张截图的不同裁剪、同一份日志的两行，不是两路。
2. **结论不能大于覆盖范围**：截了 320 宽，就只能说 320 宽；截了默认态，就不能说七态都正常。
3. **视觉通过的最低证据**：覆盖声明范围的全景 B 加局部 B，或一条像素 A；单个局部截图最多支撑它拍到的那个区域。

## 3. 模型只做候选

视觉模型可以帮忙找问题，但不能替人判通过。模型输出一律先记成候选，不直接写进 07 的状态列。

| 候选编号 | 区域 | 模型说法 | 改写成可测判据 | 验证路线 | 结论 |
|---|---|---|---|---|---|
| M-01 | 设置页保存区 | “按钮和说明文字有点挤” | 按钮矩形与说明文字矩形是否相交；间距是否小于 8px | 结构 / 几何 | 成立 / 不成立 / 未验证 |
| M-02 | 空状态 | “好像少了一个主操作” | 空状态是否有可点击的主操作，且点击后有下一步 | 交互 / 像素 | 成立 / 不成立 / 未验证 |
| M-03 | 深色主题 | “对比度可能不够” | 文字与背景的对比度是否达到 4.5:1 | 像素 / 颜色采样 | 成立 / 不成立 / 未验证 |

规则：

- 模型的“整体看起来不错”“应该没问题”是 C 级自述，永远不能判通过。
- 模型说“这里有问题”也只是候选；必须落到一条可测判据，再由三路中的至少一路确认或推翻。
- 模型候选不能直接变成“未通过”；未验证的候选留在候选表，不写进账本的证据列。
- 同一候选被推翻也要留记录，避免下一轮重复提。
- 模型可以生成测试路径、截图清单和边界条件，但这些仍然要实际执行。

## 4. 可测判据

视觉判据尽量用读数，不用形容词。下面是默认门槛；整体基线是 WCAG 2.2 [S1]，项目有更严规范时就高不就低。

| 判据 | 默认门槛 | 怎么取证 | 来源 |
|---|---|---|---|
| 正文对比度 | 4.5:1；大字号 3:1 | 采样文字色与背景色，算对比度 | [S2] |
| 非文字控件对比度 | 3:1 | 采样边框、图标、焦点环与相邻背景 | [S3] |
| 键盘焦点 | 每个可交互元素都有可见焦点，且不被浮层遮挡 | Tab 走一遍，截图或读焦点环像素 | [S4] [S12] |
| 目标尺寸 | 至少 24×24 CSS px；触控场景基线 44×44（本技能包约定） | 读按钮边界；点击热区不能小于可见边界 | [S5] |
| 200% 字体 | 内容不丢、不截断、不重叠、不需要横向滚动 | 字体放大到 200% 后重走七态 | [S6] |
| 320 CSS px 回流 | 不出现二维滚动；内容按单列重排 | 窄档截图加 `scrollWidth` 读数 | [S7] |
| 减少动效 | 系统开启“减少动态效果”时，非必要动画停止或缩短 | 切换系统偏好后重走加载/错误态 | [S8] |
| 重叠与截断 | 元素矩形不相交；文字不溢出容器；省略号必须能读到全文 | 结构读数加截图；像素采样边界 | 本文件约定 |
| 层级与遮挡 | 浮层、提示、焦点环不被裁切或盖住 | 打开所有浮层，逐层检查 | 本文件约定 |

对比度、目标尺寸和焦点环必须用读数；只凭肉眼说“够清楚”不算。颜色值要记录具体色值或截图路径，不能只写“蓝色”。焦点样式可以用 `:focus-visible` 实现 [S9]，但实现方式不等于判据，最终仍看焦点是否可见。

## 5. 独立例子：设置页的保存区

下面是一个可以直接照做的完整小例子。它不依赖 `SKILL.md`，只依赖本文件的七态、三路和判据。

### 5.1 任务卡（节选）

| 字段 | 内容 |
|---|---|
| 任务编号与版本 | VS-DEMO-01 / v1 |
| 视觉目标 | 在 320、768、1280 三档宽度下，设置页保存区的七态都可见、可操作、不遮挡说明文字 |
| 参照物 | `tokens-v3`；基线截图 `baseline-2026-11-06.png` |
| 视口矩阵 | 320×640、768×800、1280×800；100% 字体；浅色主题 |
| 七态矩阵 | 7 态 × 3 视口；每格必须有一张截图或一条结构读数 |
| 验收项 | AC-1 七态齐全；AC-2 按钮目标不小于 44×44；AC-3 文字对比度不小于 4.5:1；AC-4 空状态有主操作、错误态有重试 |
| 三路取证 | 结构、像素、交互各至少一条 |
| 模型候选 | M-01 按钮与说明文字是否相交；M-02 空状态是否缺主操作 |
| 版本锚点 | commit `abc1234`；浏览器与字体版本写进环境列 |
| 执行者 / 复核者 | 执行者甲 / 复核者乙 |

### 5.2 证据包

把每个状态的读数写成一个 JSON 文件，作为结构路线和覆盖检查的输入：

```json
{
  "task": "VS-DEMO-01",
  "viewports": [320, 768, 1280],
  "states": {
    "default":  {"button": {"w": 120, "h": 44, "contrast": 5.82}, "text_fit": true, "in_bounds": true},
    "hover":    {"button": {"w": 120, "h": 44, "contrast": 7.85}, "text_fit": true, "in_bounds": true},
    "selected": {"button": {"w": 120, "h": 44, "contrast": 10.04}, "text_fit": true, "in_bounds": true},
    "disabled": {"button": {"w": 120, "h": 44, "contrast": 5.13}, "text_fit": true, "in_bounds": true},
    "loading":  {"button": {"w": 120, "h": 44, "contrast": 5.82}, "text_fit": true, "in_bounds": true},
    "empty":    {"button": {"w": 120, "h": 44, "contrast": 5.82}, "text_fit": true, "in_bounds": true},
    "error":    {"button": {"w": 120, "h": 44, "contrast": 6.57}, "text_fit": true, "in_bounds": true}
  }
}
```

检查器只做覆盖和门槛检查；数值必须来自实际测量，不能反过来编数值让检查器通过：

```python
import json

data = json.load(open("visual-evidence.json", encoding="utf-8"))
required = {"default", "hover", "selected", "disabled", "loading", "empty", "error"}
assert set(data["viewports"]) == {320, 768, 1280}
assert set(data["states"]) == required
for name, row in data["states"].items():
    button = row["button"]
    assert button["w"] >= 44 and button["h"] >= 44, name
    assert button["contrast"] >= 4.5, name
    assert row["text_fit"] is True and row["in_bounds"] is True, name
print("PASS: 7 states x 3 viewports; target >= 44x44; contrast >= 4.5")
```

实际跑出来的示例读数：

```text
PASS: 7 states x 3 viewports = 21; min_target=44x44; min_contrast=5.13; overflow=0; empty/error next-step=OK
```

三路分别留下的证据：

| 路线 | 证据 | 读数 | 等级 |
|---|---|---|---|
| 结构 / 几何 | `visual-evidence.json` | 21 个状态×视口组合；按钮 120×44；全部在容器内 | A |
| 像素 / 视觉 | 每个状态一张截图；采样按钮底色 `#1f5fd0`，文字白色 | 对比度 5.82:1；与令牌一致 | A |
| 交互 / 路径 | 从设置页按 Tab 到保存按钮，再按 Enter；再走悬停、禁用、加载、空、错误路径 | 焦点环可见；错误态有重试；空态有主操作 | B |

### 5.3 模型候选怎么落

- M-01 “按钮和说明文字有点挤”：读两个矩形，若相交或间距小于 8px，判成立；否则记“不成立”，附边界读数。
- M-02 “空状态好像少了一个主操作”：看空状态截图和交互路径；没有可点击的“添加设置”则成立，记未通过；有则记“不成立”。
- 两个候选都不能直接写“通过”；只有对应的结构/像素/交互证据才能改变账本状态。

### 5.4 落到 07 的一行

```text
| VS-DEMO-01-AC1 | 七态在 3 档视口可见且不遮挡 | 给定 320/768/1280 宽，七态截图和结构读数均应齐全，元素边界不相交 | A 或 B+B | A | evidence/visual-evidence.json；evidence/default-320.png | 通过 | 复核者乙 |
```

一行只放一个结论。截图路径、JSON 路径和读数都写进同一行，不另开“总体评价”。

## 6. 收口自检

- [ ] 任务卡写清了视口、主题、字体缩放和七态矩阵。
- [ ] 七态矩阵里的每一个视觉状态都有证据；没有“这个状态没时间看”的格子。
- [ ] 三路证据来自不同通道，不是三张同源截图。
- [ ] 模型候选全部有“成立 / 不成立 / 未验证”的落点，没有被当成结论。
- [ ] 对比度、目标尺寸、焦点和回流至少各有一条读数。
- [ ] 07 里一个验收项一行；v1 状态只用四种（旧八列只用七种），不写“基本可用”。
- [ ] 证据锚定到本次 commit 或构建号；旧截图没有混进来。
