# 界面优化参考

> 本文件可独立使用。它只处理“业务行为不变、只改呈现与视觉状态”的优化；不改数据、不加能力。视觉验收仍按 `references/visual.md`。

## 0. 适用边界

本流程适用于“觉得丑 / 不够清楚 / 不够整齐”一类优化：形态、尺寸、颜色、对比、位置、间距、层级。

不适用于：

- 行为或状态错了（点了没反应、状态没刷新、数据不对）→ 走 `references/bug-fix.md`。
- 要加新能力、新入口、新数据 → 走 `references/new-feature.md`。
- 视觉优化同时改变行为或数据 → 拆成两条记录，分别按对应流程处理，不混在一个任务卡里。

## 1. 设计侧：先判“该不该改”

### 1.1 指认

先给现状：哪个界面、哪个状态、哪个视口、哪个元素；截图或可定位的界面读数；一句话说清“哪里不对”。指认不出具体元素，说明问题还没到可执行状态，先补观察。

### 1.2 归因四问

对每个候选问题问四句，每句用两把尺：项目自己的设计规范/令牌，以及同类界面的参照系。

| 维度 | 要回答 | 常见错判 |
|---|---|---|
| 形态 | 这个元素是不是用错了类型（按钮/链接/标签/卡片）？ | 把该换形态的问题当成换颜色 |
| 尺寸 | 字号、行高、间距、点击区是否在规范档位？ | 只凭“看起来小”调数值 |
| 颜色与对比 | 前景/背景、边框、禁用态、悬停态是否达到 `visual.md` 的对比门槛？ | 把品牌色当豁免 |
| 位置与间距 | 对齐、分组、留白、滚动区是否按栅格和层级？ | 用零散 padding 修结构问题 |

规范缺失时，记一条“规范缺口”，按同类界面选一个可解释的参照；不要把个人偏好写成规范。

### 1.3 定根因

把根因写成一句可验证的话：**因为 __，所以当前呈现为 __；应改为 __，判据是 __。**

形态问题先答三问：实际是什么、应是什么、改哪一步会变。三问答不出，不要进入实现。

同时列出“硬缺陷”（溢出、遮挡、点击区不足、对比不足、焦点不可见）；硬缺陷优先于审美偏好，不能拿“整体风格”压过去。

### 1.4 出方案

给 2–3 个方案，每个写清：改什么、影响哪些界面/状态、是否符合现有规范、成本、风险。优先复用现有令牌和同类组件；没有理由不新增一套样式。

方案必须由能承担范围的人拍板；没有拍板就停在设计侧，不先改代码再补理由。

## 2. 落地侧：改完要能证明

### 2.1 实现

- 先看工作区状态，保留已有改动；只改拍板范围内的文件。
- 查同类界面已有写法，优先复用组件、变量、令牌；不新建平行体系。
- 颜色、字号、间距、圆角、阴影走项目设计令牌；没有令牌系统时，至少集中定义，不散落硬编码。
- 不改业务逻辑、数据结构、接口和权限；需要改时回到 0 节重新分流。

### 2.2 门禁

按项目适配层 `.verity/adapter.json` 的 commands 跑构建、静态检查和视觉检查；不手抄一份门禁清单。跳过某项要记 `skipped` 和原因，不能把 skipped 当通过。

### 2.3 视觉验收

按 `references/visual.md` 做七态 × 视口矩阵，至少覆盖亮/暗主题（项目有时）和窄/宽两档；人工看前后对比，机器读像素/几何/对比度。截图必须包含被测项和能定位版本的界面；只截“好看的一角”不算。

### 2.4 收尾

- 清理本次临时截图、脚本和中间产物；保留的证据按任务卡登记。
- 用户能感知的外观变化写进更新日志（按 `references/release.md` 的写法）；纯内部重构不写。
- 关键改动按 `references/bug-fix.md` 的独立复核要求换一个上下文复核；复核意见只作参考，不替代验收。
- 按 `references/acceptance.md` 落 07，v1 三包结论（旧八列三态）收口；视觉项用 `visual.md` 的证据等级，不用“看起来顺眼”判通过。

## 3. 常见失败

- 把“丑”当根因，没有指认真实元素和规范档位。
- 只给一个方案，或者先改再补方案。
- 形态错了却靠调颜色、加阴影遮。
- 只改一个主题/一个宽度，窄窗或暗色下溢出。
- 硬编码颜色，下一轮主题切换又坏。
- 门禁 skipped 却写通过；只跑构建不看画面。
- 视觉验收只凭肉眼扫一眼，没有像素/几何读数。

## 4. 自检

- [ ] 任务卡写清“只改视觉、不改行为/数据”，并列出不做什么。
- [ ] 指认、四问、根因、方案四步都有记录；方案已拍板。
- [ ] 改动只落在拍板范围，使用既有令牌/组件。
- [ ] 门禁全过或 skipped 有记录，没有把跳过当通过。
- [ ] 七态/视口/主题覆盖，截图与读数都能定位版本。
- [ ] 07 有对应行，状态与证据等级符合 `acceptance.md` / `visual.md`。
- [ ] 临时产物已清理，更新日志已判断。
