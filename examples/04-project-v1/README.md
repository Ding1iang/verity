# 示例四：验收——项目 v1 十列账本

> 本目录是“验收模式”的样例：任务卡先定靶，执行者只取证判级，不改代码；结论只从 07 账本读出。示例项目和读数均为演示数据。

## 输入

一个已经实现完成、等待验收的候选版本。验收者拿到任务卡后，只做三件事：

1. 按任务卡的验收项逐条取证，不扩大范围。
2. 把每条证据写进十列账本，证据必须能落到文件或命令读数。
3. 按账本状态收口，不凭印象写“通过”。

## 任务卡

见 [`task-card.md`](task-card.md)（v1）。示例只有一条验收项，用来演示项目自有十列格式如何被通用检查器识别。

## 文件说明

| 文件 | 作用 |
|---|---|
| `README.md` | 验收输入、命令、预期输出和反例说明 |
| `task-card.md` | 验收任务卡（定靶） |
| `07-验收回归清单.md` | 唯一状态源（十列账本） |
| `bad-fake-screenshot/07-验收回归清单.md` | 反例：写了截图类型但没有可读截图文件 |

## 如何复跑

在仓库根目录执行：

```bash
python3 scripts/check_evidence.py examples/04-project-v1/07-验收回归清单.md \
  --format v1 --root examples/04-project-v1
```

也可以省略 `--format v1`，让检查器按 marker 自动识别。项目接入适配层后，`--adapter` 会同时提供项目根、模板格式和枚举。

## 预期输出

```text
[OK] <仓库根>/examples/04-project-v1/07-验收回归清单.md：1 行，结论=通过（通过 1）
```

退出码为 0。这里的 0 只表示账本格式与状态自洽，不表示业务验收真实通过；证据内容仍要由复核人核对。

## 反例

截图是证据类型，不是“写一句见截图”。下面这个账本把证据类型写成“截图”，证据只写“见截图”，没有图片路径：

```bash
python3 scripts/check_evidence.py examples/04-project-v1/bad-fake-screenshot/07-验收回归清单.md
```

预期看到 `E_SCREENSHOT`：

```text
[FAIL] .../bad-fake-screenshot/07-验收回归清单.md:29 [E_SCREENSHOT] ... 的证据类型是截图，但没有可读的截图文件
检查失败：1 项错误，0 项警告
```

## 这个例子演示了什么

- 验收模式不改代码：证据来自执行者的实际观察和命令读数，不来自实现者的自述。
- 项目可以有自己的列名和枚举，但必须通过适配层声明，不能靠检查器猜。
- 任务卡、07 账本和证据文件要能互相对上；同一目录只能有一份 07。
- 截图、日志、布局树等证据类型各自有最低要求，写“见截图”不算交付。
