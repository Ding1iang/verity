# 示例二：修缺陷——标签大小写导致过滤不到

> 本目录是“修缺陷从复现到独立复核”的样例。示例项目、版本号和测试读数为演示数据；真实任务必须换成自己的实测记录。

## 输入

缺陷报告（用户原话）：

> 标签明明是 `work`，我输入 `--tag Work` 就显示没有匹配。大小写不同不是同一个标签吗？

预期：标签过滤不区分大小写。实际：大写输入返回空结果，退出码仍是 0，看起来像“真的没有”。

## 任务卡

见 [`task-card.md`](task-card.md)（v1）。四条验收项覆盖原缺陷、相邻路径、错误路径和数据兼容。

## 01–04 记录摘要

完整流程本应留下四份记录；这里为控制篇幅，把要点合并到本节。

| 记录 | 要点 |
|---|---|
| 01 缺陷记录 | 缺陷 ID BUG-07；影响 `list --tag` 全部用户；首次发现 2026-11-06 08:30；状态已修复待复核 |
| 02 复现记录 | 前置：3 条书签，标签分别为 `work`、`work`、`life`。步骤：执行 `bookmark list --tag Work`。实际输出 0 条、退出码 0；预期输出 2 条。每次必现 |
| 03 根因分析 | 日志显示过滤前的标签集合是 `work|work|life`，比较参数是 `Work`；首次分叉在过滤函数：它用区分大小写的字符串比较，而上游保存标签时统一转成了小写。根因陈述：当标签含大写输入时，过滤函数把 `Work` 与存储的 `work` 当成不同标签，于是返回空；应先把输入归一化为小写再比较 |
| 04 修复与回归记录 | 修复：过滤前对输入做小写归一化，并补 4 条测试；修复前测试红（2 失败），修复后全绿。回归：原缺陷、相邻标签、空标签、既有数据四类均有读数。独立复核：复核者按 02 重跑，确认修复前失败、修复后通过，diff 无计划外改动 |

## 如何复跑

在仓库根目录执行：

```bash
python3 scripts/check_evidence.py examples/02-bug-fix/07-验收回归清单.md
```

## 预期输出

```text
[OK] <仓库根>/examples/02-bug-fix/07-验收回归清单.md：4 行，结论=通过（通过 4）
```

退出码为 0。

## 反例

修复后重新跑一遍就写通过，但如果证据日期早于本次 commit，就是复用了旧证据。下面这个账本故意把行日期写成 2026-10-01，并把 commit 指向一个真实的历史提交：

```bash
python3 scripts/check_evidence.py examples/02-bug-fix/bad-old-evidence/07-验收回归清单.md
```

预期看到 `E_STALE`：

```text
[FAIL] .../bad-old-evidence/07-验收回归清单.md:29 [E_STALE] 证据日期 2026-10-01 早于 commit 日期 2026-11-06，不能复用旧证据
检查失败：1 项错误，0 项警告
```

## 这个例子演示了什么

- 先复现再动手：`02` 里同时写了预期和实际，失败可重复。
- 根因四问答全，根因陈述能被修复结果验证；不写“代码写错了”。
- “修复前红、修复后绿”不是一句话，而是两侧读数。
- 数据兼容单独验收：过滤是只读操作，不能顺手改写书签文件。
- 复核人不是修复作者；没有独立复核时只能记“待复核”，不能写通过。
