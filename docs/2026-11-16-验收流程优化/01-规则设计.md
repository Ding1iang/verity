# 01 规则设计：入口视觉专项、R1、R2（影子批前版本）

> 阶段：1/5 ｜ 日期：2026-11-16 ｜ 目标文件：`docs/2026-11-16-验收流程优化-目标与执行计划.md`
> 本文件只是影子批用的检查清单，不修改 verity 模板与检查器；只有影子批指标达标后才进入 v1.4。
> 基线：46 条历史缺陷（11-08 32 + 11-12 8 + 11-13 6）；R3 已在 v1.3.5。

## 0. 设计原则

1. 每条规则必须能回答四个问题：拦什么问题、判据怎么写、谁执行、每批多花多少时间。
2. 规则只覆盖一类失败，不写成“万能检查表”；一条规则不能解释的缺陷，明确分给别的规则或不覆盖。
3. 判据必须能读出数字或确定状态；⛔ 不用“正常/可见/流畅/符合预期”。
4. 规则先在影子批里证明有效，再改模板/检查器；⛔ 不先落模板再找理由。
5. 发现产品缺陷时只登记，不在本目标里修；修复另开批次。

## 1. 入口与视觉专项（E1）

### 1.1 要拦的问题

功能入口存在但用户找不到、入口默认不可见、两个控件命中区重叠、文本越出父容器、同一动作多个叫法。典型历史样本：更改颜色没反应、标签入口缺失、标签 +N 与日期重叠、插入链接没输入框、待办中心没新建入口、标签 chip 不高亮、反馈跳应用市场、页签缺批量关闭、模板名差一个字找不到。

### 1.2 三项检查

| 检查 ID | 检查什么 | 判据 | 证据 |
|---|---|---|---|
| E1.1 入口清单 | 受影响区域的每个可见入口：左栏、顶栏、页面卡、空态、弹窗、底部工具行 | 默认态下入口存在、可见、可点；点击后有可见变化；⛔ 不靠补造前置证明入口存在 | 控件树 `text/id/bounds/enabled/clickable` + 整窗截图 |
| E1.2 边界 | 同一层控件的两两 bounds 交集；文本/子控件是否越出父容器；状态行、时间行、按钮行 | 同层可点击控件交集面积 = 0 px²；文本右/下缘 ≤ 父容器右/下缘；装饰性热区不计入 | 控件树 bounds；溢出按父/子右缘或下缘差值记录 |
| E1.3 命名 | 同一动作在菜单、Toast、撤销条、空态、按钮上的动词；功能标题与动作名 | 同一动作只用一套动词；同一功能标题与动作名不互相冲突；专有名词按项目术语表 | 字符串资源键 + 实际界面文本 |

### 1.3 触发条件

- 改左栏、顶栏、页面卡、页签、空态、弹窗、底部工具行、窗口布局的批次：三项全跑。
- 只改数据层、搜索算法、导入解析的批次：不跑，写“本批无界面入口变化”。
- 只改单个文案的批次：只跑 E1.3，不跑 E1.1/E1.2。

### 1.4 执行方式

1. 任务卡先列“受影响入口清单”，每个入口一行；没有清单不许开工。
2. 取证时先整窗截图，再读控件树；每个入口点一次，记录可见变化。
3. E1.2 用项目现有的 bounds 分析脚本（入口视觉专项的 `bounds-analyzer.py` 或等价脚本）输出交集/溢出表。
4. E1.3 对照字符串资源和界面实际文本，列出“动作 → 菜单写法 / Toast 写法 / 撤销条写法 / 空态写法”。
5. 结果写入 07 的专项行，不另造第二套状态。

### 1.5 成本与误报风险

- 成本：每批约 20–30 分钟；入口多的批次按入口数线性增加。
- 误报风险：低到中。主要风险是把“图标热区大于图形”误报成重叠，或把“设计上允许的省略号”误报成溢出。
- 排除规则：装饰性命中区、透明焦点代理、弹窗遮罩不属于同层重叠；文本省略但 bounds 在父容器内不算溢出。

### 1.6 不达标就砍

- 9 条 gap 里覆盖 <8 条，或影子批误报 >1 次/批：先收窄检查项；连续两批不达标就砍掉该检查项。
- E1.1 不能退化成“把所有按钮点一遍”；必须只列受影响入口，否则不计覆盖。

## 2. R1 形态×数据矩阵

### 2.1 要拦的问题

只在某种窗口形态或数据状态下出现的缺陷。典型：空库左栏版式、窄窗设置裁切、满页签写日记、PC 最大化与自由窗口差异。

### 2.2 规则写法

任务卡增加两列：`形态`、`数据`；每个受影响模块至少落一行，不要求全矩阵。

| 形态 | 数据 | 何时用 |
|---|---|---|
| PC 最大化 3120×1955 | 空库（只有首页/默认笔记本） | 首启、空态、左栏空态、全屏布局 |
| PC 自由窗口 2090×1394 | 页签满 8 个 + 满库 | 页签、列表、卡片、弹窗、窄窗 |
| 窄窗 986×1394（约 519vp） | 单笔记本 / 空库 | 覆盖层、响应式断点、设置 |
| 平板 1440×960 | 单笔记本 | 仅在目标批次声明平板时加 |

起步只跑两个固定组合：① PC 最大化 × 空库；② PC 自由窗口 × 页签满。其余组合按改动面按需加，⛔ 不要求每批全跑。

### 2.3 执行方式

- 任务卡写清本批选哪两行、为什么选；不选的行写“不适用 + 理由”。
- 取证时每个组合至少一张整窗截图 + 一个关键读数（布局树 bounds 或 DB 计数）。
- 结果写入 07 的对应 AC，不另建“矩阵通过”总表。

### 2.4 成本与误报风险

- 成本：两个固定组合约 1–2 小时/批（造空库、满页签、切窗口）。
- 误报风险：低；主要风险是“为凑矩阵而造无关数据”，所以只对受影响模块落行。
- 不达标：额外工时 >2 小时且没有新增拦截，砍到只保留一个组合。

## 3. R2 键鼠路径

### 3.1 要拦的问题

触摸/鼠标能通、键盘路径不通，或反过来。典型：搜索结果键盘导航、菜单 Esc 关闭、页签 F10、设置齿轮 Tab、右键菜单。

### 3.2 规则写法

验收项表增加 `输入方式` 列：触摸 / 鼠标 / 键盘。受影响模块至少：

- 一条纯键盘 AC：写清 Tab / 上下 / 回车 / Esc / Back 的具体顺序；
- 一条鼠标 AC：写清右键、悬停、点击目标。

不要求每个 AC 都三路覆盖；只要求受影响模块至少各有一条。

### 3.3 执行方式

- 键盘：`uitest uiInput keyEvent` 单键可用；组合键必须先做正对照，正对照不成立记“未覆盖-注入通道无原语”，⛔ 不许写成通过。
- 鼠标：右键、悬停、点击分别取证；宿主级注入禁用，只用设备侧通道。
- 结果写入 07，失败保留输入现场和焦点/选中读数。

### 3.4 成本与误报风险

- 成本：约 1 小时/批；仅交互入口批次启用。
- 误报风险：低；主要风险是把“组合键注入不了”误报成产品缺陷。
- 不达标：额外工时 >1.5 小时且无新增拦截，或连续两批误报 >1，降为按需。

## 4. R3 不变量（已落，影子期复核）

### 4.1 规则

每条 AC 除“给定……应得到……”外，必须写一个跨区域不变量，四选一：当前页是目标 / 计数与内容一致 / 焦点落点 / 跨区域内容一致。

### 4.2 影子期记录

- 写卡时间（分钟/条）；
- 取证时间（分钟/条）；
- 误报次数（旧构建/新构建被不变量误判）；
- 漏检次数（本应拦住但没拦住）。

### 4.3 不达标

- 写卡 >5 分钟/条，或误报 >1 次/批：收窄不变量类型或回退到 v1.3.5 前口径。

## 5. 三条规则的分工

| 缺陷类型 | 首选规则 | 说明 |
|---|---|---|
| 状态不对：计数/当前页/焦点/内容不一致 | R3 | 断言带跨区域不变量 |
| 只在某形态/数据下出现 | R1 | 固定组合优先 |
| 触摸/鼠标/键盘路径不一致 | R2 | 输入方式单列 |
| 入口缺失、默认不可见、控件重叠、文本越界、命名不一致 | E1 | 入口清单 + bounds + 术语 |
| 纯数据/算法问题 | 不在本目标 | 由现有验证或另立专项 |

## 6. 影子批任务书模板（只附清单，不改 verity 模板）

```text
本批附加检查（影子）：
1. 入口与视觉：列出受影响入口 → 逐项点 → 读 bounds 交集/溢出 → 对命名。
2. R1：本批选形态×数据两行：____；不选的行写理由。
3. R2：受影响模块至少一条纯键盘 AC + 一条鼠标 AC；组合键先做正对照。
4. R3：每条 AC 带一个跨区域不变量和读数。
记录：本可提前拦住的反馈数 / 额外工时 / 误报返工数。
```

## 7. 设计阶段结论

四条规则（E1、R1、R2、R3）的分工已经闭合；E1 是新增项，R1/R2 是待验证项，R3 是已落地待影子复核项。下一阶段用 46 条语料做纸面回测，并对 E1 的 9 条 gap 做真回放；回测不达标就不进入影子批。
